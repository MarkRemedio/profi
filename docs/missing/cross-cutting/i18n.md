# Internationalisation / localisation

**Status:** Missing
**Category:** Cross-cutting

## What this is

Multi-language UI plus locale-aware formatting of numbers, currency, and dates — and a clear separation between presentation locale and accounting _base currency_.

## Current state

- All UI strings hard-coded in English in [components/](../../../components/).
- Currency enum is GBP/USD/EUR only ([prisma/schema.prisma:90](../../../prisma/schema.prisma#L90)).
- No `next-intl` / `next-translate` / `react-i18next` configured.
- Money formatted ad-hoc in [lib/accounting/money.ts](../../../lib/accounting/money.ts) (look at file to confirm locale handling).

## Why it's needed

- WAW group is global; serving non-UK orgs in English-only blocks expansion.
- Date format mismatches (US vs EU) cause real bookkeeping bugs when CSVs are imported.

## Recommended approach

- `next-intl` (best App Router story).
- Extract strings into `messages/{locale}.json`; English first, then add languages on demand.
- Use `Intl.NumberFormat` and `Intl.DateTimeFormat` everywhere — never `toFixed(2)` for money.
- Per-user locale, per-org base currency, per-document document currency — these are three different things and need to stay distinct.

## Implementation notes

- Money values stay in minor units (`BigInt`) — only format at the edge.
- Don't translate accounting terms loosely (e.g. "Accounts receivable" has a specific meaning per jurisdiction).
